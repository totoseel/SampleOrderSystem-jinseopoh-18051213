# PRD — S-Semi 반도체 시료 생산주문관리 시스템

## 1. 배경 및 목적

가상의 반도체 회사 **S-Semi**는 연구소·팹리스 업체·대학 연구실 등에 반도체 시료(Sample)를 납품한다.  
기존 엑셀·메모장 기반 관리는 주문 누락, 공정 현황 파악 불가, 불필요한 추가 공정 발생 등의 문제를 야기했다.  
이를 해결하기 위해 **콘솔(CLI) 기반 생산주문관리 시스템**을 개발한다.

---

## 2. 역할 구성

| 역할 | 행동 |
|------|------|
| **고객** | 필요한 시료를 이메일로 요청 |
| **주문 담당자** | 요청에 맞게 주문서 작성·관리, 출고 처리 |
| **생산 담당자** | 개발 시료 등록, 주문 수신 후 승인 또는 거절 |

---

## 3. 시스템 범위

- **인터페이스**: 콘솔(CLI), 담당자가 직접 번호 메뉴 입력
- **생산 라인**: 단일 라인, 시료를 하나씩 생산, 주문된 시료에 대해서만 생산
- **영속성**: JSON 파일 기반 (애플리케이션 재실행 후에도 데이터 유지)
- **범위 외**: 인증/인가, GUI, 네트워크 통신

---

## 4. 기능 요구사항

### 4-1. 메인 화면

메인 화면 진입 시 시스템 현황 요약을 항상 표시한 뒤 메뉴를 제공한다.

**현황 요약 표시 항목**
- 등록 시료 수
- 총 재고 수량
- 전체 주문 수
- 생산라인 대기 수
- 현재 생산 중인 시료 정보 (없으면 "생산 없음")
- `CONFIRMED` 상태(출고 대기) 주문 수

**메뉴 구성 (6개)**

| 번호 | 메뉴 |
|------|------|
| 1 | 시료 관리 |
| 2 | 시료 주문 |
| 3 | 주문 승인/거절 |
| 4 | 모니터링 |
| 5 | 생산라인 |
| 6 | 출고 처리 |

### 4-2. 시료 관리

| 서브메뉴 | 입력 | 처리 |
|----------|------|------|
| 시료 등록 | 시료 ID, 이름, 평균 생산시간(분), 수율, 초기 재고 수량 | 중복 ID 거절, 저장 |
| 시료 목록 조회 | — | 전체 시료 + 현재 재고 수량 표시 |
| 시료 검색 | 이름(부분 일치) | 일치하는 시료 목록 출력 |

- 등록된 시료만 주문 가능하다.
- **수율(Yield)**: 정상 시료 수 / 총 생산 시료 수 (예: 100개 중 90개 정상 → 0.9), 범위: `0 < yield ≤ 1`
- **초기 재고 수량**: 시료 등록 시 함께 입력하며 0 이상 정수

### 4-3. 시료 주문 (접수)

- 입력: 시료 ID, 고객명, 주문 수량 (1 이상 정수)
- 등록되지 않은 시료 ID 입력 시 오류
- 생성 직후 상태: `RESERVED`
- 주문번호 형식: `ORD-YYYYMMDD-NNNN` (당일 순번 4자리, 재시작 후에도 순번 유지)

### 4-4. 주문 승인/거절

- `RESERVED` 상태 주문 목록을 표시한 뒤 처리할 주문을 선택한다.
- **승인** 처리 시:
  - 재고 ≥ 주문 수량 → 재고 차감 후 즉시 `CONFIRMED`
  - 재고 < 주문 수량 → 생산라인 자동 등록 + `PRODUCING`
- **거절** 처리 시 → 즉시 `REJECTED`

### 4-5. 모니터링

**주문량 확인**
- 상태별 건수 표시: `RESERVED`, `PRODUCING`, `CONFIRMED`, `RELEASE`
- `REJECTED`는 표시하지 않는다.

**재고량 확인**
- 시료별 현재 재고 수량 표시
- 재고 상태 라벨:

| 라벨 | 조건 |
|------|------|
| 여유 | 주문 대비 재고 충분 |
| 부족 | 주문 대비 재고 수량 부족 |
| 고갈 | 재고 수량 = 0 |

### 4-6. 생산라인

- **스케줄링**: FIFO (선입선출)
- **실 생산량**: `ceil(부족분 / (수율 × 0.9))`
- **총 생산시간**: `평균 생산시간(분) × 실 생산량`
- 생산 완료 시 해당 주문을 `PRODUCING → CONFIRMED`으로 자동 전환하고 재고를 반영한다.

**표시 정보**

| 구분 | 표시 항목 |
|------|-----------|
| 현재 생산 중 | 주문번호, 시료명, 진행률(%), 완료 예정 시각 |
| 대기 큐 | 순서, 주문번호, 시료명, 주문량, 부족분, 실 생산량, 예상 완료 시각 |

### 4-7. 출고 처리

- `CONFIRMED` 상태 주문 목록을 표시한다.
- 특정 주문 선택 → 출고 실행 → `RELEASE` 전환

---

## 5. 주문 상태 흐름

```
RESERVED ──► (승인) ──► 재고 충분? ──► YES ──► CONFIRMED ──► RELEASE
                                   └──► NO  ──► PRODUCING ──► CONFIRMED ──► RELEASE
         └──► (거절) ──► REJECTED
```

| 상태 | 의미 |
|------|------|
| `RESERVED` | 주문 접수 완료, 승인 대기 |
| `REJECTED` | 주문 거절 (모니터링 제외) |
| `PRODUCING` | 승인 완료, 재고 부족으로 생산 중 |
| `CONFIRMED` | 출고 대기 중 |
| `RELEASE` | 출고 완료 |

## 7. 생산 진행률 및 시간 설정

### 7-1. 진행률 계산 방식

생산 진행률은 **실시간 시각 기반**으로 계산한다.

```
진행률(%) = (현재시각 - 생산시작시각) / 총 생산시간 × 100
완료 예정 시각 = 생산시작시각 + 총 생산시간
```

- 진행률이 100%에 도달하면 `PRODUCING → CONFIRMED` 자동 전환
- 대기 큐의 예상 완료 시각은 앞선 항목의 완료 예정 시각을 기준으로 순차 계산

### 7-2. 시간 배율 설정 (Time Scale)

실제 운영 시간과 시스템 내부 시간 사이의 배율을 CLI 인수로 주입한다.

- **CLI 인수**: `--time-scale <배율>` (기본값: `1.0`)
- 배율 예시: `--time-scale 60` → 현실 1초 = 시스템 1분으로 가속

```bash
# 현실 1초를 시스템 1분으로 가속하여 실행
./gradlew run --args="--time-scale 60"
```

- 배율은 양의 실수(`> 0`)만 허용하며, 잘못된 값 입력 시 기본값 `1.0` 적용
- 테스트 환경에서는 `TimeProvider` 인터페이스를 통해 시각을 주입하여 실시간 의존성을 제거한다.
